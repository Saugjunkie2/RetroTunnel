LESEHINWEIS
================================================================================
Diese Liste definiert die Reihenfolge, in der Themen abgearbeitet werden.
Die Reihenfolge basiert auf Abhängigkeiten: Jeder Schritt setzt voraus,
dass die vorherigen Schritte mindestens als Entwurf existieren.

Legende:
  [DONE]     = Abgeschlossen
  [ACTIVE]   = Aktuell in Arbeit
  [NEXT]     = Nächster Schritt nach Abschluss des aktuellen
  [WAITING]  = Wartet auf Vorgänger
  [DEFERRED] = Bewusst zurückgestellt (spätere Phase)

NAMENSKONVENTION (MUST, Drift-Guard):
  M0..M4 = Modellphasen (RetroTunnel-Konzeptarbeit)
    M0 = Fundament, M1 = Denkmodell, M2 = Kern-Module,
    M3 = Erweiterungsmodule, M4 = Decisions/Proofs/Implementation
  PH1..PH10 = Rollout-Phasen / Funktionsbereiche
    Definition + Acceptance: siehe 04_PHASE_PLAN.txt (SOLL-Liste)
    Uebersicht: PH1 = VPN-Baseline, PH2 = QoS, PH3 = DNS,
                PH4 = CA/Webstack, PH5 = Webpanel Core,
                PH6 = Operability, PH7 = Accounting,
                PH8 = Restricted Mode, PH9 = Monitoring,
                PH10 = Extras
  KEINE Verwechslung: "M1 ist fertig" != "PH1 ist fertig".
  M-Phasen beschreiben Konzeptarbeit (diese Datei: IST-Liste),
  PH-Phasen beschreiben Funktionsbereiche/Betrieb (04_PHASE_PLAN.txt: SOLL-Liste).

NUMMERIERUNG: Seit 2026-04-16 konsequent 3-stellig.
  Base-Ordner: BASE-000 bis BASE-110.
  Dateinummern innerhalb Ordnern: 000, 010, ..., 090, 095.
  Module: MOD-001 bis MOD-010.
  Arbeitspakete M2-xxx folgen der Base-Nummer.

MODELLPHASE M2 — KERN-MODULE (base/)
================================================================================
Warum nach Model? Die Base-Module implementieren das Denkmodell.
Ohne Model gibt es keine klaren Eingaben/Ausgaben.

Reihenfolge innerhalb M2 basiert auf der kritischen Kette:
SQL-First -> Platform -> Identity -> AAA -> Tunnels -> Firewall ->
DNS -> Session -> Policy-Apply -> Settings -> Policy -> Web

     - ICMP Rate-Limiting pro User (Ping-Flood-Schutz)

     - Outbound Connection-Rate-Limiting (Brute-Force ueber VPN)
     - Port-Scan-Erkennung und Begrenzung
