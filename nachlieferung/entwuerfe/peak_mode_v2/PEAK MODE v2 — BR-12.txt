================================================================================
0) SCOPE (MUST)
================================================================================
Dieses BR definiert ausschließlich:
- Hardening Contracts (Caps/Rate-Limits) für:
  a) Apply-Invocation Rate (BR-09)
  b) State-Transition Rate (BR-10)
  c) Snapshot/Audit Volume (BR-08)
  d) Manual Overrides (BR-10/Panel)
- Circuit-Breaker Regeln (when to pause/disable) bei wiederholten Fehlern
- Lock contention policy (wie mit wiederholtem LOCKED umgehen)
- DB down policy (keine Eskalation, kein spam)
- AuthZ Contract: wer darf welche Manual Actions ausführen + optional rate-limit pro admin

Anti-Scope:
- Trigger Messlogik (BR-03)
- State machine selbst (BR-10), außer “caps über transitions”
- Apply intern (BR-09) außer “caps über invocations”
- DB Schema (BR-08) außer “retention/volume constraints”
- Panel-Views (BR-11) außer “Welche Buttons existieren + permissions”

================================================================================
3) HARDENING CONTRACT (MUST)
================================================================================

3.1 Global Guard Rails (MUST)
GR-12-01 Single-Writer bleibt Pflicht (BR-09 Lock). BR-12 darf nicht parallel “work around”.
GR-12-02 Apply darf nie schneller laufen als Controller-Tick, aber zusätzlich gilt APPLY_MIN_GAP_SEC.
GR-12-03 Jeder “suppressed” Apply-Versuch wird auditierbar gemacht (reason: RATE_LIMIT/CIRCUIT_OPEN/etc.)
GR-12-04 Circuit Breaker darf niemals Manual FORCE_EXIT blockieren (Not-Aus).

3.2 Apply Rate-Limits (MUST)
RL-APPLY-01 Minimum Gap
- Wenn (now - last_apply_started_at) < APPLY_MIN_GAP_SEC:
  - Controller darf BR-09 nicht aufrufen.
  - Stattdessen: record “APPLY_SUPPRESSED: MIN_GAP” (in episode or run meta).
  - State machine bleibt stabil: PEAK_ACTIVE bleibt aktiv; hold_until kann weiter sliden, aber apply ist suppressed.

RL-APPLY-02 Window Cap
- Wenn apply_count_10min >= APPLY_MAX_PER_10MIN:
  - suppress apply (reason WINDOW_CAP)
  - set hardening_flag=RATE_LIMIT_ACTIVE sichtbar in BR-11.

RL-APPLY-03 Failure Backoff (bounded)
- Wenn Apply fails wiederholt:
  - increment consecutive_fail_count
  - wenn consecutive_fail_count >= APPLY_MAX_CONSEC_FAIL:
      open circuit (CIRCUIT_OPEN)
      suppress further applies (außer Manual FORCE_EXIT)

3.3 Transition Caps (anti-flap) (MUST)
RL-STATE-01 Enter/Exit Caps
- ENTER transitions pro Stunde <= ENTER_MAX_PER_HOUR
- EXIT transitions pro Stunde <= EXIT_MAX_PER_HOUR
- Bei Überschreitung:
  - Force COOLDOWN extension oder Force DISABLED (Owner policy) — OPEN
  - audit reason: FLAP_GUARD

RL-STATE-02 Cooldown Bypass Policy
- MANUAL_ENTER cooldown bypass nur wenn COOLDOWN_BYPASS_POLICY=ALLOW
- zusätzlich MANUAL_MAX_ACTIONS_PER_5MIN beachten.

3.4 Snapshot/Audit Volume Caps (MUST)
RL-AUDIT-01 Snapshot Rate
- snapshots werden maximal SNAPSHOT_MAX_RATE geschrieben (z.B. 6/min).
- Wenn tick schneller: downsample (keep last in window).
- audit: “SNAPSHOT_DOWNSAMPLED”

RL-AUDIT-02 apply_item policy
- apply_item rows können bei sehr großen N teuer sein.
- Policy bestimmt:
  - ALWAYS: jedes item loggen
  - FAIL_ONLY: nur failures + aggregated ok
  - DEBUG_ONLY: only when debug flag enabled (admin)
- Muss in BR-11 sichtbar sein (“detail level”).

3.5 Manual Overrides Hardening (MUST)
AUTHZ-12-01 Actions
- FORCE_ENTER: allowed roles = AUTHZ_ROLES_FOR_ACTIONS.force_enter
- FORCE_EXIT: allowed roles = ...force_exit
- DISABLE_PEAK/ENABLE_PEAK/CLEAR_EPISODE: allowed roles = …
- Jede Manual Action erzeugt audit event (who-role, when, action, reason string) ohne PII.

RL-MAN-01 Manual Rate Limit
- pro admin identity/session <= MANUAL_MAX_ACTIONS_PER_5MIN
- bei überschreitung: action rejected (reason MANUAL_RATE_LIMIT) + audit

Invariant:
- FORCE_EXIT ist Not-Aus: darf durch circuit/rate-limit nicht blockiert werden,
  aber AuthZ muss erfüllt sein.

4) CIRCUIT BREAKER CONTRACT (MUST)
================================================================================

4.1 Circuit States (MUST)
C0 CLOSED (normal)
C1 OPEN (apply suppressed)
C2 HALF_OPEN (limited trial apply allowed)

4.2 Circuit Open Conditions (MUST)
- OPEN on:
  - consecutive_fail_count >= APPLY_MAX_CONSEC_FAIL (exit_code in {2,4,6,7})
- Optional OPEN on LOCKED storm:
  - wenn CIRCUIT_OPEN_ON_LOCKED = true und locked_count_window >= threshold
- Optional OPEN on DB down:
  - wenn DB_DOWN_POLICY = “suppress until ok”

4.3 Open Behaviour (MUST)
- Während OPEN:
  - Controller darf BR-09 nicht aufrufen (außer FORCE_EXIT)
  - State machine kann trotzdem PEAK_ACTIVE bleiben; hold_until kann sliden
  - Panel zeigt CIRCUIT_OPEN + remaining time (open_until)

4.4 Half-Open Trial (MUST)
- Nach CIRCUIT_OPEN_MIN_SEC:
  - switch to HALF_OPEN: allow max 1 apply attempt
  - if success (exit_code 0/1): close circuit, reset counters
  - if fail: reopen for another CIRCUIT_OPEN_MIN_SEC (bounded)

================================================================================
5) EDGE CASES / FAILURE MODES (MUST)
================================================================================

E-12-01 LOCK contention storm
- Repeated exit_code=5:
  - treat as “system busy”; optional circuit open on locked if configured.
  - Do not spin.

E-12-02 DB audit fails (disk full / DB down)
- If cannot write audits, system must avoid infinite attempts.
- Policy OPEN:
  - Option A: disable peak (S5) after X audit failures
  - Option B: keep running but minimal in-memory counters (risk)
  -> Owner should fix.

E-12-03 High active_ppp (100+)
- apply_item logging may explode.
- enforce APPLY_ITEM_LOGGING_POLICY (FAIL_ONLY or DEBUG_ONLY recommended at scale).

E-12-04 Manual misuse / panic clicking
- manual rate limit protects system
- panel shows “manual rate limited”.

6) DoD / TESTS / VALIDATION (MUST)
================================================================================

T-12-01 Apply min gap
- Trigger frequent ticks/overload:
  - ensure apply calls are suppressed inside gap; audit reason MIN_GAP present.

T-12-02 Window cap
- Force > APPLY_MAX_PER_10MIN attempts:
  - ensure cap triggers; circuit not necessarily open; panel shows RATE_LIMIT_ACTIVE.

T-12-03 Circuit open on fails
- Simulate BR-09 exit_code=4 for N times:
  - after APPLY_MAX_CONSEC_FAIL: circuit opens; no more applies except FORCE_EXIT.

T-12-04 Half-open trial
- After open duration:
  - exactly 1 trial apply; success closes circuit; failure reopens.

T-12-05 Lock storm behaviour
- Simulate repeated exit_code=5:
  - ensure no busy loop; optionally circuit opens if configured.

T-12-06 Manual action authz
- Unauthorized role:
  - action rejected + audit.
- Authorized role:
  - action executes + audit.

T-12-07 Manual rate limit
- Spam manual actions:
  - rejects after limit; audit reason MANUAL_RATE_LIMIT.

T-12-08 Scale audit volume
- active_ppp=200:
  - apply_item policy prevents DB blow-up (FAIL_ONLY or DEBUG_ONLY), downsample snapshots.
