================================================================================
N-05.1 Grundsatz: /diag ist Support/CI Input, scope-gebunden
================================================================================
MUST:
- /diag nur über VPN erreichbar (B270).
- /diag Ausgabe scope-abhängig (restricted/user/admin):
  • USER/RESTRICT: keine sensiblen Detailwerte (keine kompletten settings dumps)
  • ADMIN: erweiterte Trace-Infos

(OPEN: Feinheitsgrad, siehe DEC-SQLF-012 OPEN)

================================================================================
N-05.2 Neues Sub-Objekt (Additive, B270-kompatibel)
================================================================================
Additiv (unter /diag root) — keine breaking changes:

A) backend.db_state (oder vorhandenes Feld erweitern)
- db_state: OK | DOWN | UNKNOWN
- reason_code: (B342 kompatibel; z.B. R_AUTH_BACKEND_SQL_DOWN/FAIL)
- observed_at

B) backend.settings (health summary)
- catalog_version / schema_version (falls vorhanden)
- required_keyset_id (welches Key-Set gilt für diese Phase/Domain)
- completeness: true/false
- drift_flags: array of DRIFT_* (NORM-03)
- last_resolve_ms / timeout_flag (Meta)

C) backend.settings_trace (ADMIN-only)
- Für eine kleine, begrenzte Menge Keys (Key-Set, nicht “alles”) liefert /diag pro key:
  • canonical_key
  • effective_value (redacted wenn nötig)
  • effective_source (GLOBAL/CUSTOMER/CONNECTION/FALLBACK_*)
  • key_state (OK/MISSING/INVALID/FALLBACK_ACTIVE/DB_UNKNOWN)
  • reason_code
  • alias_used (optional)

MUST:
- Trace muss size-limited sein (Disk/Net/DoS).
- Kein PII, keine Secrets (B270).

================================================================================
N-05.3 Failure-Map Exposure (Expected Fails)
================================================================================
SQL-first verlangt: Wenn ein Key fehlt/invalid ist, darf das nicht “mystisch” sein.
Daher /diag muss für die Phase ein “expected_fail_map_id” referenzieren können:
- expected_fail_map_id (z.B. PH2_EXPECT_FAILS_v3)
- mismatches_count

(Details in NORM-07 B310 Proof Plan)
