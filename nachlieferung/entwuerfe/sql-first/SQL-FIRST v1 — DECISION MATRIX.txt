NORMATIVITÄT (MUST):
- Diese Matrix ist der zentrale “Index” der Entscheidungen.
- Jede Entscheidung hat: DEC-ID, Status (FIX/OPEN), kurze Aussage, Impact (PH/F/NX),
  Referenzen (Kanon-Datei/Abschnitt oder Entwurfs-Norm).
- FIX heißt: Owner hat entschieden (siehe OWNER-FIX VALUE SHEET).
- OPEN heißt: noch nicht final; wird NICHT implizit entschieden.

ARBEITSMODUS (Entwurfspflege; NON-RUNTIME):
- Zusätzlich zum Status (FIX/OPEN) kann eine DEC als Entwurfsarbeit mitgeführt werden via:
  • PH_BINDING: CORE | PH1..PH10  (früheste Phase, in der die DEC spätestens FIX sein muss)
  • WORK_STATUS: ACTIVE | DEFERRED (aktueller Fokus im Entwurf)
  • BLOCKS: NONE | PH1..PH10      (welche Phase wäre ohne diese DEC blockiert)
- Ableitung (wenn nicht explizit gesetzt):
  • PH_BINDING: kleinste PH aus „Impact: PH…“; wenn keine PH genannt → PH_BINDING=PH10 (konservativ)
  • WORK_STATUS: ACTIVE, wenn PH_BINDING=CORE oder PH_BINDING <= FOCUS_PHASE; sonst DEFERRED
  • BLOCKS: default NONE; nur explizit setzen, wenn wirklich „PHx kann nicht closed sein ohne FIX dieser DEC“
- Guardrail: WORK_STATUS/PH_BINDING/BLOCKS steuern nur Priorisierung/Backlog im Entwurf – sie ändern nicht die Semantik von FIX/OPEN.

DM-SQLF-KEYHARVEST-01 (FIX): Unpräfixierte Legacy-Keys im Kanon sind NUR Alias.
- Canonical Keys folgen strikt der Präfix-Norm (web_/vpn_/peak_/radius_).
- Key-Harvest v1 Canonical: web_ip_pool_{green,red}_threshold, web_log_*, web_spool_*, web_settings_cache_ttl_seconds.
- Begründung: verhindert Namenswildwuchs, verbessert Panel-UX, reduziert Drift im Alias-Resolver.

DM-SQLF-KEYHARVEST-02 (FIX): Die 8 Harvest-Keys werden als echte settings_catalog Einträge geführt.
- Status: REQUIRED (weil Kanon sie als SQL-first/policy-relevant referenziert).
- Umsetzung: SQLF-CATADD-01 spezifiziert Typ/Constraints/Fail-Class/Diag/Proof; Defaults bleiben OWNER-FIX-OPEN bis final entschieden.
Refs: SQLF-HARVEST-01; SQLF-CATADD-01; NORM-01; NORM-07

DM-SQLF-KEYHARVEST-03 (FIX): Disk-Safety Keys nutzen Fail-Class „tighten-only“.
- Betrifft: web_log_* + web_spool_* (Retention/MaxBytes)
- Regel: Bei missing/invalid darf fallback niemals loosening sein (nie höhere Caps/Retention).
Refs: NORM-03; SQLF-CATADD-01; NORM-07 (KH-004)
