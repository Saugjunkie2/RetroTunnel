================================================================================
N-06.1 Key-Set Konzept (MUST)
================================================================================
Ein Key-Set ist eine benannte Liste required keys, die in settings_catalog existieren müssen,
damit eine Phase als “konzeptuell geschlossen” gelten kann.

Key-Set hat:
- keyset_id (z.B. PH2_REQUIRED_KEYS_v1)
- phase (PH1..PH10)
- domain (optional: QoS/DNS/Panel/AAA)
- required_keys: list of canonical keys
- optional_keys: list (nice but not required for closure)
- consumers: list of canonical consumer blocks (Bxxx)
- proof_ids: list of B310 tests that prove completeness + correctness
- expected_fail_map_id

================================================================================

================================================================================
N-06.4 DoD (wann ist ein Key-Set “grün”?)
================================================================================
Ein Key-Set gilt als “geschlossen” wenn:
- alle required_keys existieren im catalog (NORM-01)
- resolver liefert OK/FALLBACK_ACTIVE korrekt (NORM-02)
- /diag zeigt completeness + drift flags (NORM-05)
- B310 Proofs existieren und sind eindeutig (NORM-07)

================================================================================
N-06.5 Bootstrap-Prerequisite (SQL-first “DB existiert” Gate) (MUST)
================================================================================
Ziel:
- PH-Keyset-Closure setzt voraus, dass die Datenbank als Source-of-Truth bereits existiert.
- Kein “Runtime-Fallback” auf Defaults/Magic-Numbers: wenn DB/Scheme/Seed fehlt -> fail-closed.

MUST (konzeptionell, implementierungsneutral):
- Vor PH1-Test/Proof-Läufen muss der DB-Bootstrap einmalig erfolgt sein:
  - Schema vorhanden (mindestens settings_catalog + settings_value; weitere Tabellen gemäß B055/B057-SoT).
  - Seed vorhanden: alle required_keys des jeweiligen keyset_id existieren im catalog.
- Runtime-Regel: Resolver/AAA/Policy lesen Settings ausschließlich aus DB (SQL-first).
- Fail-Closed: Wenn DB nicht erreichbar / Schema unvollständig / required_keys fehlen:
  - keine “silent defaults”; Dienste gehen in BLOCKED/MAINTENANCE (keine PH1-Proofs “grün” möglich).
- Validierung (DoD-Hook):
  - /diag zeigt DB-State und keyset completeness (NORM-05).
  - B310-Tests dürfen PH1 nur als “geschlossen” markieren, wenn Bootstrap-Prerequisite erfüllt ist (NORM-07).
