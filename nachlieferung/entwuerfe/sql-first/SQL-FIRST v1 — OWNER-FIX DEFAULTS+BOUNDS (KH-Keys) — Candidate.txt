A) Cross-Key Constraints (MUST zuerst lesen)
================================================================================

DEC-SQLF-KH-CROSS-001 (STATUS: OPEN)
- Thema: Beziehung ip_pool_red_threshold < ip_pool_green_threshold
- Ziel: Ampel-Logik ist deterministisch und verhindert widersprüchliche Zustände.
- Regel (Entwurf):
  • Es MUSS gelten: 0 < web_ip_pool_red_threshold < web_ip_pool_green_threshold
- Option A (strict-fail):
  • Wenn verletzt: Settings gelten als INVALID → Fail-Class greifen → Reason-Code + /diag drift/invalid Flag.
- Option B (auto-adjust):
  • Wenn verletzt: System korrigiert intern (z.B. red := min(red, green-1)) UND setzt Drift/Warning.
- Constraints:
  • Keine stille Korrektur ohne sichtbaren Hinweis im Panel (/diag).
- Validierung:
  • B310-SQLF-KH-007 (Relation): invalid-reason + expected-fail/expected-warning.

B1) Pool-Ampel (B061) — Units: “Slots” (allocatable slots; Tail-Reserve bereits abgezogen)
--------------------------------------------------------------------------------

DEC-SQLF-KH-101 (STATUS: OPEN) — web_ip_pool_green_threshold
- Canonical Key: web_ip_pool_green_threshold
- Legacy Alias: ip_pool_green_threshold
- Type/Unit: INT (slots)
- Semantik: GREEN wenn free_slots >= green_threshold
- Default (CANDIDATE): default = 30
- Bounds (CANDIDATE):
  • min = 5
  • max = (allocatable_slots - 1)   (harte Beziehung zu pool size; muss zur Laufzeit validierbar sein)
- Fail-Class-Intention:
  • invalid → tighten-only (nie “loosen”), weil falsche Ampel falsche Ops-Entscheide triggern kann
- /diag Erwartung:
  • settings.trace zeigt effective_value, source(sql/alias/fallback), validity=OK/INVALID
- Validierung:
  • B310-SQLF-KH-001 (Presence)
  • B310-SQLF-KH-006 (Bounds)
  • B310-SQLF-KH-007 (Relation, zusammen mit red)

DEC-SQLF-KH-102 (STATUS: OPEN) — web_ip_pool_red_threshold
- Canonical Key: web_ip_pool_red_threshold
- Legacy Alias: ip_pool_red_threshold
- Type/Unit: INT (slots)
- Semantik: RED wenn free_slots < red_threshold
- Default (CANDIDATE): default = 10
- Bounds (CANDIDATE):
  • min = 1
  • max = (web_ip_pool_green_threshold - 1)  (Relation)
- Fail-Class-Intention: invalid → tighten-only
- Validierung: B310-SQLF-KH-001 / -006 / -007

HINWEIS:
- Defaults sind abhängig von Pool-Größe (z.B. /24 vs /23) und Tail-Reserve.
- Ziel ist “sinnvoller Startwert”, nicht “universell korrekt”.

B2) Settings-Load Strategy (B330) — Units: Sekunden
--------------------------------------------------------------------------------

DEC-SQLF-KH-201 (STATUS: OPEN) — web_settings_cache_ttl_seconds
- Canonical Key: web_settings_cache_ttl_seconds
- Legacy Alias: settings_cache_ttl_seconds
- Type/Unit: INT (seconds)
- Zweck: TTL für gecachte Settings (DoS/Latency Schutz) — policy value aus SQL
- Default (CANDIDATE): default = 60
- Bounds (CANDIDATE): min = 5 ; max = 300
- Physik-Ceiling (OPEN): local_cap_seconds = 300 (wenn Cap-Modell aktiv)
- Fail-Class-Intention:
  • missing/invalid → fallback = 60s (klar markiert; Reason-Code)
  • sql>cap → drift/warn + effective_value begrenzt (wenn Cap aktiv)
- Validierung:
  • B310-SQLF-KH-002 (Validation)
  • B310-SQLF-KH-004 (Diag Trace)
  • B310-SQLF-KH-008 (Cap behaviour, falls aktiv)
