2) Begriffe / Matrix-Legende (verbindlich für dieses DOC-SET)
----------------------------------------------------------------------

Begriffe:
- Initiator:
  Wer löst die Aktion aus (USER | ADMIN | SYSTEM | DAEMON).
- Writer:
  Komponente, die persistenten Zustand schreibt (SQL | /run | spool | logs/audit).
  Hinweis: “persistenter Zustand” bedeutet: etwas, das nach Prozess-Neustart/Retry noch relevant ist
  (SQL, /run-Files, Locks, spooled ops, audit events).
- Enforcer:
  Komponente, die Policy technisch erzwingt (AAA | nft | tc | web_gate | system_gate).
- Truth Source:
  Wo “die Wahrheit” in dieser Domäne gilt (SQL vs /run vs radacct vs kernel state).
- Drift-Detector:
  Kanonische Stelle, die Drift/UNKNOWN sichtbar machen MUSS (B052/B057/B270/B166/B167 etc.).

Write-Surfaces (Kurz-Norm):
- SQL:
  persistent, normativ, policy-relevant (settings_*; identity objects; locks object).
- /run:
  runtime bridge / session mapping / apply state; darf nicht “manuell” hotfixbar sein (Drift-Risiko).
- spool (falls genutzt):
  transient/backpressure; darf niemals “Truth Source” für Policy sein; nur Queue/Transport.
- logs/audit:
  bounded/rotated; Events als Nachweis/Diagnose, nicht als Policy-Quelle.

Grundsatz (MUST):
- USER schreibt niemals direkt in SQL.
- ADMIN schreibt Policy nur über Panel-Gates (AuthZ/Validation/Audit).
- SYSTEM/DAEMON schreibt /run und Kernel-Enforcement nur als deterministische Ableitung aus SQL.

4) Write-Path-Contract Regeln (WP-00x) — was MUSS gelten
----------------------------------------------------------------------

WP-001 — Canonical-Only Writes (MUST)
- Ziel:
  Writers schreiben ausschließlich canonical Keys (nicht Aliases).
- Delta/Anker:
  Durchsetzung über PR-PFX-005 (No-Alias-Write) + Registry/Resolver Gate.
- Grenzen/Constraints:
  SQL-first; keine stillen Sonderwege; Legacy-Clients sind irrelevant für Write-Path (Server-seitig).
- Validierung:
  /diag.settings_registry.summary.alias_write_attempts == 0 im Normalbetrieb; Audit-Events bei Verstoß.

WP-002 — No-Alias-Write (Split-Brain Prevention) (MUST)
- Referenz:
  DOC-SET-PR-PFX / PR-PFX-005.
- Observability (MUST):
  /diag.settings_registry.summary.alias_write_attempts
  Audit Event: ALIAS_WRITE_ATTEMPT
- Gate:
  CI-005 (Policy/Security Gate)

WP-003 — Conflict Detection (Alias + Canonical Divergence) (MUST)
- Referenz:
  DOC-SET-PR-PFX / PR-PFX-006.
- Observability (MUST):
  /diag.settings_registry.state=CONFLICT
  /diag.settings_registry.top_conflicts[] (key_id + names + reason)

WP-004 — USER darf keine Policy schreiben (MUST)
- Ziel:
  USER kann Claim/Verify auslösen, aber keine Policy/Settings schreiben.
- Delta/Anker:
  B345 Write-Path-Grundsatz + Panel AuthZ (B280/B285) + AAA separation (B056).
- Validierung:
  Versuche eines USER-Write müssen fail-closed + auditiert sein (Reason/Outcome Normen).

WP-005 — Apply/Reconcile ist die einzige SQL→Kernel Brücke (MUST)
- Ziel:
  nft/tc/DNS Enforcement entsteht ausschließlich durch SYSTEM Apply/Reconcile (deterministisch).
- Delta/Anker:
  B166/B167; keine manuellen Hotfixes in kernel state ohne Trace.
- Validierung:
  Apply-Trace + /diag expected-vs-effective; idempotent Re-Run erzeugt keinen Drift.

WP-006 — Audit-Minimum für Registry/Resolver Events (MUST)
- Ziel:
  Jede relevante Registry/Resolver Aktion ist auditierbar (ohne value-leak).
- Delta/Anker:
  DOC-SET-REGISTRY (Reason/diag Felder) + Audit-Minimalfelder (actor, key_id, before/after hash, timestamp, reason_code).
- Validierung:
  Audit-Stream/Log zeigt Events; keine stillen Auto-Fixes ohne Event.

5) Violation Handling / Actions (nur deterministische Aktionen)
----------------------------------------------------------------------

VH-001 — ALIAS_WRITE_ATTEMPT
- Problem:
  Writer versucht Alias statt Canonical zu schreiben → Split-Brain Risiko.
- Action (MUST):
  reject/fail-closed + Audit Event ALIAS_WRITE_ATTEMPT + Counter increment.
- Observability:
  /diag.settings_registry.summary.alias_write_attempts
  (Optional detail fields in DOC-SET-REGISTRY: last_violation, violating_writer_component)

VH-002 — CONFLICT_DETECTED (alias+canonical divergence)
- Action (MUST):
  canonical gewinnt als effective; alias quarantined (nur Diagnose/Audit); keine stille Fusion.
- Observability:
  /diag.settings_registry.state=CONFLICT
  /diag.settings_registry.top_conflicts[]
  Audit: CONFLICT_DETECTED

VH-003 — BACKEND/DB-State Unsicherheit (DB_UNKNOWN)
- Action (MUST):
  fail-closed für Policy-Changes; Apply muss deterministisch degradieren; keine “ban on backend error”.
- Observability:
  DB_STATE / DB_UNKNOWN Gründe gemäß B052 + Ausgabe in /diag (B270)
