B) Was “FIX Apply” später konkret bedeutet (ohne Patch/Copy-Blöcke)
================================================================================
B1) Owner-Aktion (ein Satz reicht später):
- “KH Fix-Pack ACCEPT BASELINE: alle oben gelisteten DEC auf FIX setzen.”

B2) Danach gelten die Candidate Defaults/Bounds als “Owner-FIX”:
- In “OWNER-FIX DEFAULTS+BOUNDS (KH-Keys) — Candidate” wird pro DEC:
  STATUS: OPEN → STATUS: FIX
- In “DECISION MATRIX” werden die DEC-Status ebenfalls auf FIX gespiegelt.
- In “OPEN REGISTER” schließen sich:
  SQLF-OPEN-KH-FIX-ALL und SQLF-OPEN-KH-CROSS-REL.

================================================================================
C) Proof-/Ops-Auswirkungen (B310 / /diag)
================================================================================
C1) Expected-Fails werden deterministisch:
- B310-SQLF-KH-006 (Bounds) kann echte Grenzwerte testen.
- B310-SQLF-KH-007 (Relation) kann strict-fail testen (Reason + /diag trace).

C2) /diag Vertrag (NORM-05) kann “effective_value + source + reason” stabil ausweisen.
