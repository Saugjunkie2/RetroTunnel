================================================================================
C) /diag Semantic Notes (für Panel-UX)
================================================================================
C1) STRICT-FAIL+Fallback:
- invalid value → effective_value aus SAFE FALLBACK
- /diag:
  • validation_state=INVALID
  • source=DEFAULT (oder SAFE_FALLBACK)
  • reasons: SETTINGS_INVALID (+ optional SETTINGS_FALLBACK)

C2) Cap aktiv:
- SQL value > cap → effective_value=cap_value
- /diag:
  • source=CAPPED
  • validation_state: OK oder DEGRADED (je nach Settings-State Modell)
  • reasons include SETTINGS_CAPPED

C3) DB_OK vs SETTINGS_STATE:
- DB_OK bleibt DB_OK, solange Backend gesund ist.
- SETTINGS_STATE zeigt degradations.
