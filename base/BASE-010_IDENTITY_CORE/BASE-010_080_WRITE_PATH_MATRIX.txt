8) RANDFAELLE UND ATOMIZITAET (MUST)
================================================================================

  R1) Doppel-Claim: Idempotent. SYSTEM prueft atomar
      (Transaction + SELECT ... FOR UPDATE).
  R2) Verify-Idempotenz: Mehrfaches Verify = kein Schaden.
  R3) Rollenwechsel (T-09): In-place Mutation (access_role + ip_slot
      auf derselben Connection). Aktive Sessions beenden (Hard-Cut).
      Alte Connection wird NICHT geloescht — sie bekommt neuen Slot.
  R3b) Tunnel-Typ-Wechsel: tunnel_type ist immutable (VC-08).
      "Wechsel" = alte Connection loeschen + neue erstellen.
      Alte revoked/disabled gemaess Policy.
  R4) DB_DOWN: Fail-closed. Kein "halbes" Provisioning.
      Keine "best effort" Writes in Core.
