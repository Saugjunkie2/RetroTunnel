1) ZWECK
================================================================================

  BASE-030 beschreibt den L2TP/IPsec-Tunnelpfad fuer Windows XP/Vista
  Clients. Der Pfad nutzt zwei entkoppelte Daemons:

    strongSwan  — terminiert IKEv1/IPsec (Phase 1+2, PSK, NAT-T)
    accel-ppp   — terminiert L2TP + PPP (Auth via RADIUS, IP-Vergabe)

  Die Daemons kommunizieren NICHT direkt miteinander. Der Linux
  XFRM-Stack (Kernel) entkapselt eingehende ESP-Pakete bevor sie
  accel-ppp auf UDP/1701 erreichen. Ausgehend verschluesselt XFRM
  den Klartext-L2TP-Traffic automatisch via SA-Policy.

  KONSISTENZFEHLER-AUFLOESUNG: Das alte Konzept (B040) nennt
  xl2tpd + pppd als L2TP/PPP-Stack. Der Live-Server nutzt accel-ppp.
  RetroTunnel kanonisiert accel-ppp als einzigen L2TP/PPP-Daemon.
  Begruendung: Ein Prozess statt drei, eingebaute RADIUS-Anbindung,
  eingebautes Session-Management, eingebauter Shaper, aktiv gepflegt.

6) PANEL-CONSUMABILITY (R-17)
================================================================================

  - accel-ppp Session-Status: accel-cmd show sessions (CLI) →
    Panel zeigt aktive L2TP-Sessions mit User, IP, Interface, Uptime
  - strongSwan SA-Status: swanctl --list-sas →
    Panel zeigt aktive IPsec-SAs mit Peer-IP, Proposals, Rekey-Timer
  - PSK-Einsicht: Panel zeigt Klartext-PSK fuer ADMIN (R-17,
    Begruendung: User braucht PSK fuer selbstaendigen VPN-Aufbau).
    Jede Einsichtnahme wird im Audit-Log protokolliert.
    Bewusste Security-Ausnahme: PSK ist ein Group-Secret, kein
    individuelles Credential. Bei PSK-Leak: Massen-Email + Rotation.
  - Crypto-Proposals: Panel zeigt welche Algorithmen aktiv verhandelt
    werden (Monitoring, kein Einstellen — Crypto ist fix)
  - LCP-Echo Status: Panel zeigt Dead-Peer-Detection Zustand pro Session
  - accel-ppp Fehler-Log: Panel-Log-Viewer liest auth-fail.log
