BASE-005 — SERVICE INVENTAR
================================================================================
DATEI: BASE-005_070_SERVICE_INVENTAR.txt
STATUS: ACTIVE

ZWECK:
  Einzige Quelle fuer "welche systemd-Units existieren im System".
  Jeder Dienst hat einen Owner-Base, eine Rolle und einen Typ.
  Die LIFECYCLE-Datei (080) baut auf diesem Inventar auf.

================================================================================
1) INVENTAR-SCHEMA
================================================================================

  Jeder Eintrag:
    Unit-Name         Die konkrete systemd-Unit
    Owner-Base        Welche Base beschreibt die Fachlogik
    Typ               core / helper / job / timer
    Rolle             Was der Dienst tut (1 Satz)
    Kritisch          Ja / Nein / Bedingt
    User              Linux-User (Referenz auf BASE-005_050)

4) JOB-DIENSTE (periodisch, alle 60s systemd-Timer-Tick)
================================================================================

  Alle Timer verwenden OnUnitActiveSec=60s als Wiring-Tick.
  Das effektive Intervall wird per SQL-Setting gesteuert (Gating
  im Service: noop wenn Intervall nicht erreicht). Quelle: B167 §6.

  Unit + Timer                        Owner       SQL-Setting
  ----------------------------------- ----------- ---------------------------
  vpn-policy-reconcile.service        BASE-080    vpn_reconcile_interval_seconds
  vpn-policy-reconcile.timer                      (>= 60s, SQL-first)

  vpn-accounting-collector.service    BASE-070    radius_acct_interim_seconds
  vpn-accounting-collector.timer                  (>= 60s, SQL-first)

  vpn-stale-session-janitor.service   BASE-070    janitor_interval_seconds
  vpn-stale-session-janitor.timer                 (>= 60s, SQL-first)

  LOCKING: Jeder Job nutzt flock unter /run/ (Single-Writer).
  Bei Lock-Kollision: sauberer Abbruch (TEMPFAIL_LOCKED).
