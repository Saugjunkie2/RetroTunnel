1) WARUM BASE-005?
================================================================================

Jeder Dienst im System (MariaDB, FreeRADIUS, WireGuard, strongSwan,
nftables, Unbound, AdGuard, OpenResty, PHP-FPM, Janitor, Reconcile, ...)
braucht die gleichen Fundament-Fragen beantwortet:

  - Unter welchem Linux-User laufe ich?
  - An welche IP/Port binde ich?
  - Wo liegen meine Config-Files, Logs, State?
  - Wo leben meine Secrets?
  - Wann darf ich starten (wer muss vorher bereit sein)?
  - Was bedeutet "bereit" fuer meinen Dienst?
  - Was passiert bei Crash / Reload / Shutdown?

Wenn diese Fragen in jeder Base einzeln beantwortet werden, entsteht
Drift: BASE-040 sagt /etc/wireguard/awg0.conf, BASE-050 sagt etwas
anderes, und niemand merkt es bis der Server nicht mehr bootet.

BASE-005 ist die zentrale Heimat fuer Plattform-weite Vertraege.
Analog zu BASE-000 fuer SQL-Naming, aber fuer OS/Betrieb/Laufzeit.

2) SCOPE
================================================================================

  WAS HIER STEHT:
  - Welche OS-Baseline das System voraussetzt
  - Service-Endpunkt-Registry (IP, Port, Bind, Interface)
  - Filesystem-Layout (Config-Pfade, State, Runtime, Logs)
  - Linux-User/Gruppen und ihre Rechte
  - Secret-Management (wo, wie, Rotation)
  - Service-Inventar (welche systemd-Units existieren)
  - Lifecycle-/Dependency-/Readiness-Vertrag

  WAS HIER NICHT STEHT:
  - SQL-Naming, Tabellen, Keys (-> BASE-000)
  - Settings-Resolution (-> BASE-090)
  - Policy-Resolution (-> BASE-100)
  - Fachliche Tunnel-/Auth-Details (-> jeweilige Fach-Base)
  - Session-Truth / Accounting-Semantik (-> BASE-070)
  - Backup-Orchestrierung (-> MOD-008)
  - Monitoring/Alerting (-> MOD-007)
  - Panel-/Business-States (-> BASE-110, MOD-006)

================================================================================
5) PFLICHT-ABSCHNITT FUER ALLE FACH-BASES
================================================================================

Jede spaetere Fach-Base (BASE-010 bis BASE-110) MUSS einen Abschnitt
"Plattform-Contract" enthalten, der folgende Punkte spezifiziert:

  a) Meine systemd-Unit(s)
  b) Mein Linux-User / Gruppen
  c) Meine Endpunkte / Ports / Bind-IPs / Interfaces
  d) Meine Pfade (Config, State, Runtime, Logs)
  e) Meine Secrets (Pfade, wer darf lesen)
  f) Meine Dependencies beim Boot (harte/weiche/async)
  g) Mein Readiness-Kriterium
  h) Mein Restart-/Reload-/Recovery-Verhalten

Die Fach-Base definiert diese Punkte NICHT neu — sie referenziert die
zentralen Registries aus BASE-005. Die Base sagt: "Ich bin Dienst X aus
dem Service-Inventar (BASE-005_070), binde an Endpoint Y (BASE-005_030),
laufe unter User Z (BASE-005_050)."
