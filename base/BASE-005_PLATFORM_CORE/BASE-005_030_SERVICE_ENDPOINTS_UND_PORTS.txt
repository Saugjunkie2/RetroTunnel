  ANCHOR-TYPEN (Klarstellung):
  Nicht alle Service-Anchors sind Bind-Adressen. Zwei Typen:
    BIND-ANCHOR: Dienst bindet tatsaechlich auf diese IP.
      .1 (AdGuardHome), .2 (Unbound), .3 (OpenResty), .4 (NTP),
      .5 (SSH), .6 (PMA)
    NON-BIND-ANCHOR: IP existiert auf lo, aber kein Dienst bindet hier.
      .10 (PPP Gateway → kein Dienst-Port, reiner Netz-Anchor)

  WARTBARKEITS-PRINZIP: Jeder Dienst bindet auf seine eigene
  Service-IP (nicht auf localhost), damit Logs sofort zeigen
  welcher Dienst beteiligt ist. Bei localhost waeren tausend
  Eintraege nicht unterscheidbar.

  NICHT ALS SERVICE-ANCHOR:
  - MariaDB: Bind auf localhost (127.0.0.1:3306) + Unix-Socket
    (/run/mysqld/mysqld.sock). Debian-Default. Kein Service-Anchor
    im 10.77.0.x Netz (kein Netzwerk-Zugriff noetig, alle Clients
    sind lokal: FreeRADIUS, PHP-FPM, VPN-Tooling).
  - FreeRADIUS: Bind auf localhost (127.0.0.1:1812/1813).
    Kein Service-Anchor im 10.77.0.x Netz.

  HINWEISE:
  - Unbound laeuft auf Port 5353 an SERVICE_RESOLVER (.2),
    NICHT auf Port 53. Port 53 gehoert AdGuardHome (.1).
    AdGuard nutzt Unbound als Upstream via .2:5353.
  - SSH auf Custom-Port 27812 (nicht Standard-22).
  - phpMyAdmin laeuft ueber Port 80 (kein TLS, keine selbst-
    signierten Zertifikate). Auth: Quell-IP-Pruefung im
    Ordner-Config (IP OK → PMA, IP Fail → 403 Forbidden).
    Zusaetzlich Kernel-Level ACL: nftables erlaubt Zugriff
    auf SERVICE_PMA (.6) NUR aus ADMIN-Pool.
