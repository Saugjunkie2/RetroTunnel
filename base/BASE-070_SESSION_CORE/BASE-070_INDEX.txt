1) ZWECK
================================================================================

  BASE-070 ist der tunnelneutrale Sitzungskern von RetroTunnel. Er legt
  fest, woran das System erkennt, dass eine Connection gerade genutzt wird
  (runtime_activity), wie gleichzeitige Nutzung auf genau eine begrenzt
  wird (SimUse=1, Sperrvertrag), wie verwaiste Zustaende beseitigt werden
  (Bereinigung), wie eine Nutzung hart beendet wird (Hard-Cut), wie
  Verbrauch genau einmal gebucht und je Abrechnungsmonat gefuehrt wird
  (Gruppe D, Quota-Periode, Tagesreihe) und wie Tunneladressen vergeben,
  gesperrt und zurueckgegeben werden (Allokator, Quarantaene).

  Leitsatz: DIE LAUFZEIT WEISS, OB EIN TUNNEL LEBT - SQL WEISS, WAS ER
  DARF UND WAS ER VERBRAUCHT HAT. Kein Datensatz wird als Lebendbeweis
  gelesen; geschlossen wird nur, was belegt tot ist; gebucht wird genau
  einmal.

  Grundlage ist D004 (Runtime-Truth vs. SQL-Persistenz) in der Fassung
  v2.0-REKONSTRUKTION. Der Modulname bleibt (D004 P-05); der Begriff
  "Session" wird als Einzelbegriff vermieden (D004-E07).

6) ZUSAGEN IM UEBERBLICK
================================================================================

  - Nie zwei Tunnel einer Connection; nie eine Uebernahme (SC-12, SC-13).
  - Aussperren durch Leichen ist begrenzt (SC-27).
  - Verbrauch wird genau einmal gebucht; eine Datenbankstoerung allein
    verliert nichts (SC-35, SC-39); Messgrenzen sind benannt (SC-40).
  - Der Monatswechsel ist atomar und protokolliert (SC-42, SC-43).
  - Adressen sind eindeutig, zufaellig gewaehlt und waehrend der
    Quarantaene gesperrt (SC-47, SC-50).
  - Ein Hard-Cut beendet die Laufzeit oder meldet ehrlich sein Scheitern
    (SC-31).

7) PANEL-CONSUMABILITY (R-17)
================================================================================

  Je Detaildatei ein Abschnitt "Panel-Consumability". Zusammengefasst
  liefert BASE-070 dem Panel: Hinweise "zuletzt gesehen" und "verbunden
  seit", Episodenverlauf, Live-Auskunft ueber den privilegierten
  Auftragsweg, Verbrauch der laufenden und vergangener Perioden,
  Tagesverlauf und Ranglisten, Pool-Ampel, Hard-Cut als ADMIN-Handlung,
  Betriebsseite mit Statusdateien, Marken und Alarmen. Das Panel
  bearbeitet weder Sperren noch Marken, Hinweisfelder oder
  Buchungsstaende.
