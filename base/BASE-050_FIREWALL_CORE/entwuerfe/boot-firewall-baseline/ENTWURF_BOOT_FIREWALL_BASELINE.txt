2) LOESUNGSOPTIONEN
================================================================================

  OPTION A — Fruehes Minimal-Ruleset (EMPFOHLEN):
  Eine kleine nftables-Unit die VOR den Tunnel-Diensten laedt.
  Inhalt: Nur Baseline-Regeln die auch ohne Tunnel-Interfaces
  funktionieren (Wildcard-Patterns):
    - FORWARD policy DROP
    - iifname "ppp*" DROP (Default-Deny fuer L2TP)
    - iifname "awg*" DROP (Default-Deny fuer WireGuard)
    - WAN input: UDP 500/4500, ESP erlaubt
    - UDP 1701 nur via meta ipsec exists
    - Alles andere: DROP

  Implementierung: nftables-baseline.service
    After=network-online.target lo-service-ips.service
    Before=strongswan.service accel-ppp.service awg-quick@awg0.service
    ExecStart=nft -f /etc/nftables-baseline.conf

  Das volle Ruleset (BASE-050) laedt danach in Phase 4 und
  ERWEITERT das Baseline-Set (nicht ersetzt).

  OPTION B — Boot-Gating von accel-ppp:
  accel-ppp.service bekommt After=nftables.service.
  Nachteil: Tunnel-Interfaces existieren dann erst nach nftables.
  BASE-005_080 §3 Phase 4 HINWEIS sagt genau dagegen:
  "Tunnel-Interfaces muessen existieren bevor nft-Regeln sie
   referenzieren koennen." Bei Wildcard-Patterns (ppp*) ist
  das aber kein Problem — Wildcards matchen auch ohne existierende
  Interfaces. Nur interface-spezifische Regeln (z.B. "awg0")
  brauchen das Interface.

  OPTION C — ip-pre-up als Belt-and-Suspenders:
  Ergaenzend zu Option A oder B: ip-pre-up setzt eine per-Interface
  DROP-Regel bevor das Interface hochkommt. Redundant zum Default-Deny
  aber zusaetzliche Schutzschicht.
